OVER 2.5 / BTTS / HOME WIN PREDICTION SYSTEM - SETUP GUIDE
=========================================================

Last updated: 2026-09-03

----------------------------------------------------------------------
PRIMARY AUTOMATION: GitHub Actions Self-Hosted Runner (Windows)
----------------------------------------------------------------------

All daily predictions, result fetching, and weekly/monthly reports now
run automatically via the GitHub Actions workflow:
  .github/workflows/run_daily.yml    (runs-on: self-hosted)

The `daily-predictions`, `weekly-report`, and `monthly-report` jobs
MUST run on a self-hosted Windows runner. The `fetch-results` job can
run on ubuntu-latest.

---
Setting up a NEW Windows self-hosted runner (one-time per machine)
---

1. Open PowerShell in the repo root and run:
      .\actions-runner-bootstrap.ps1
   It will:
     - Detect repo slug from `git remote get-url origin`
     - Download + extract the pinned runner release
     - Prompt for a 1-hour registration token from
         https://github.com/iobuyumbi/over-under/settings/actions/runners/new?arch=x64&os=win
     - Register the runner as: over-under-<COMPUTERNAME>-<YYYYMMDD>

2. The bootstrap defaults to `--runasservice false` (interactive mode).
   To switch to a Windows Service that auto-starts at boot, see the
   "Permanent Windows Service install" section below.

3. Run interactively (simplest for testing):
      cd actions-runner-local
      .\run.cmd
   The runner will print "Listening for Jobs" when connected.
   Keep the window open — closing it stops the runner.

---
Permanent Windows Service install (auto-starts with Windows)
---

As of 2026-09-03, the repo ships with helper scripts in
`actions-runner-local/` that correctly install the runner as a
real Windows Service. Earlier attempts failed because running
`RunnerService.exe start` directly always errors with:

    "Cannot start service from the command line or a debugger.
     A Windows Service must first be installed (using installutil.exe)..."

This is by design — a Windows Service .NET assembly is launched by the
SCM (Services Control Manager), never directly. Correct svc.cmd uses
`.NET InstallUtil.exe` + `net start/stop` SCM commands.

One-click install:

    File: actions-runner-local\INSTALL_SERVICE.bat
      Right-click -> Run as administrator.

    What it does (via INSTALL_SERVICE.ps1):
      1. Kills any stray Runner.Listener / RunnerService processes
      2. InstallUtil.exe bin\RunnerService.exe   (registers in HKLM\Services)
      3. Start-Service <service-name>
      4. Waits for _diag\*.log to contain "Listening for Jobs"

Manual equivalent in an ADMIN CMD window:

    cd actions-runner-local
    svc install       :: InstallUtil.exe against RunnerService.exe
    svc start         :: net start actions.runner.iobuyumbi-over-under.<name>
    svc status        :: sc query ...

Service name format: actions.runner.iobuyumbi-over-under.<agentName>
(Computed automatically by svc.cmd from .runner gitHubUrl + agentName.)

Admin check services.msc if svc start fails (logon password expired, etc.).

NOTE: actions-runner-local/ is gitignored. If you move machines, just
re-run .\actions-runner-bootstrap.ps1 on the new machine.

----------------------------------------------------------------------
LOCAL (NO-CI) QUICK START (5 minutes) - For testing without CI
----------------------------------------------------------------------

1. Install Python 3.8+ from python.org
2. Install required packages:
      pip install -r requirements.txt

3. Run the full daily pipeline locally:
      run_local.bat
   Or individual engines:
      python over25_soccerbase.py
      python btts_soccerbase.py
      python home_win_soccerbase.py

The pipeline will:
- Fetch today's matches from Soccerbase (PRIMARY data source)
- Scrape recent form + H2H for each team
- Apply per-algorithm vetoes (form symmetry, BTTS per-team 50% floor,
  home win clean-sheet / draw / overall-symmetry vetoes, O/U
  overall-scoring floor, etc.)
- Output qualified matches + curated premium/solid shortlist
  to curated.json / curated.txt

----------------------------------------------------------------------
CURATION FILTERS (for Premium / Solid shortlist)
----------------------------------------------------------------------

Only "Premium" and "Solid" tiers qualify for the shortlist:
  Over/Under      >= 70%
  BTTS Yes        >= 70%
  BTTS No         >= 68%
  Home Win        >= 85%

Plus hard exclusions for volatile leagues (MLS, J-League, Mexican,
Brazilian, etc. — see curate_picks.py LEAGUE_EXCLUSIONS).

----------------------------------------------------------------------
VETO REFERENCE (engine hard-blocks)
----------------------------------------------------------------------

Home Win vetoes:
  - Home has >= 2 draws in last 3 home games
  - Away has >= 2 clean sheets in last 3 away games
  - Overall form symmetry veto (home win% < 50% OR away win% >= 50%)

Over 2.5 overall scoring symmetry veto (per-team):
  - Home: < 1.2 gpg overall AND scored in < 4/6 overall
  - Away: < 1.0 gpg overall AND scored in < 3/6 overall
    (Either fails → O/2.5 blocked; either passes → allowed.)

BTTS overall symmetry veto (per-team 50% floor — replaced the old
combined-average check because one low-frequency team would hide
behind a high-frequency partner):
  - BTTS "Yes": BOTH teams must have >= 50% BTTS rate overall
  - BTTS "No":  BOTH teams must have >= 50% non-BTTS rate overall

Under 2.5 vetoes: blowout risk + peak high-scoring history games.

----------------------------------------------------------------------
MANUAL DATA ENTRY (when scraping fails)
----------------------------------------------------------------------

1. Copy manual_results_template.csv -> manual_results.csv
2. Fill in match rows with final scores
3. Run: python update_manual_results.py

The tracker merges manual results on the next run.

----------------------------------------------------------------------
TROUBLESHOOTING
----------------------------------------------------------------------

Runner: "svc.cmd is not recognized"
  -> svc.cmd is NOT shipped inside the runner zip. It is either
     generated by config.cmd --runasservice true, or (for v2.336+)
     must be deployed as a wrapper (ours is at actions-runner-local\svc.cmd).

Runner: "Cannot start service from the command line or debugger"
  -> Do not run RunnerService.exe install/start directly.
     Always use svc install (InstallUtil) + svc start (net start).
     Or right-click INSTALL_SERVICE.bat -> Run as admin.

Runner: stays grey/offline in GitHub Runners list
  -> Verify run.cmd or the service is actually running locally.
     Open Task Manager -> Details -> Runner.Listener.exe should exist.

"No matches found":
  -> Offseason for your leagues. Use manual_results.csv for cup rounds
     or add more leagues to LEAGUE_SOURCES in the engine scripts.

"Rate limited" / "captcha detected" / "short page":
  -> scraping.py has built-in retries, randomized headers, and TTL
     caching. If Soccerbase blocks, switch to manual_results.csv until
     the block lifts.

"Team not found":
  -> Names differ between leagues/cups. Add manual mapping to
     clean_team_name() in the engine or pre-normalize via
     team_data_manager.py.
